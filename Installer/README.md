# Crystal Bowie installers

Two independent packaging pipelines: **Windows** via [Inno Setup](https://jrsoftware.org/isinfo.php),
**macOS** via Apple's standard `pkgbuild`/`productbuild` toolchain. Both package already-built Release
plugin binaries — neither builds the plugin itself beyond an optional convenience step on Windows.

## Single source of truth for product identity

Product name, company, bundle ID, and version are defined **once**, in the repo root
[`CMakeLists.txt`](../CMakeLists.txt) (`PRODUCT_NAME`/`COMPANY_NAME`/`BUNDLE_ID`, plus
`project(... VERSION ...)`). Running `cmake -B build` expands these, via `configure_file()`, into
`build/Installer/ProductInfo.iss` and `build/Installer/ProductInfo.sh` — generated, gitignored files
that `Windows/CrystalBowie.iss` `#include`s and `macOS/build_installer.sh` `source`s. **Neither installer
script hand-maintains its own copy of these values** — change them in one place (`CMakeLists.txt`) and
re-run `cmake -B build`.

## Windows

```
cmake -B build                          # if not already configured
Installer\Windows\build_installer.ps1   # builds Release, then compiles the installer
```

Produces `Installer\Windows\Output\Crystal Bowie-<version>-Setup.exe`. Pass `-SkipBuild` if the Release
CLAP/VST3 binaries are already built. Requires Inno Setup 6 (`ISCC.exe`, checked on PATH then at its
default install location).

Installs CLAP to `Common Files\CLAP`, VST3 to `Common Files\VST3` — each independently selectable in the
installer's Components page. Crystal Bowie's VST3 is a JUCE folder bundle (not a single file like the
other Icebreaker Audio plugins' clap-wrapper builds), hence the wildcard + `recursesubdirs` in
`CrystalBowie.iss`'s `[Files]` section. LV2 is built by this project but intentionally **not** included
in the installer (Windows has no standard LV2 install-location convention, and it wasn't part of the
scope for this pass).

**Not yet wired up (needs a real certificate):** Authenticode code signing. `CrystalBowie.iss`'s
`[Setup]` section has a commented-out `SignTool=`/`SignedUninstaller=yes` pair ready to uncomment once
one exists.

## macOS

```
cd Installer/macOS
./build_installer.sh
```

Produces `Installer/macOS/Output/Crystal Bowie-<version>.pkg`, combining three `pkgbuild` component
packages (CLAP → `/Library/Audio/Plug-Ins/CLAP`, VST3 → `/Library/Audio/Plug-Ins/VST3`, AU →
`/Library/Audio/Plug-Ins/Components`) via `productbuild`, each independently deselectable in the
installer.

**This repository has never had a macOS build performed** (development so far has been Windows-only).
`build_installer.sh`'s `BUILD_DIR`/`CONFIG_SUBDIR` variables encode a best guess, based on JUCE's own
CMake output layout, at where a macOS Release build's `.clap`/`.vst3`/`.component` bundles land — verify
and adjust them on first use:
```
find build/CrystalBowie_artefacts -name "Crystal Bowie.*"
```
The script fails fast with a clear message naming the missing path if these are wrong, rather than
silently producing an empty package.

**Signing:** export `DEVELOPER_ID_INSTALLER="Developer ID Installer: Your Name (TEAMID)"` before running
to sign; omit it to build an unsigned package (fine for local testing). **Notarization** is a separate
step — see `notarize.sh` (requires `NOTARY_PROFILE`, a keychain profile created once via `xcrun
notarytool store-credentials`; uses the current `xcrun notarytool`/`stapler` flow, not the deprecated
`altool`).

## Placeholder resources — replace before shipping to real users

Generated by [`assets/generate_icons.py`](assets/generate_icons.py) (`python
Installer/assets/generate_icons.py`, re-run after replacing `assets/icon-source.png` with real artwork):
- `assets/icon-source.png` — placeholder square logo (a "CB" mark)
- `Windows/icon.ico`, `macOS/resources/AppIcon.icns` — derived from the source logo
- `macOS/resources/background.png` — placeholder installer wizard background

`Windows/License.txt` and `macOS/resources/license.rtf` are a free-software EULA adapted from
Icebreaker Audio's commercial license template (same warranty/liability/jurisdiction terms, but with
all seat-count and registration/activation language removed, since Crystal Bowie has no license key) —
still worth a legal review pass before wide distribution.

Hand-written placeholder, headed with an explicit "not legal text" notice — **replace with real
copy before wide distribution**:
- `macOS/resources/welcome.rtf` (marketing copy placeholder, not legal)

Cannot be created here at all (no fake credentials are fabricated) — must be supplied by whoever has
access to them:
- A Windows Authenticode code-signing certificate
- An Apple Developer ID Installer certificate
- Apple notarization credentials (an `xcrun notarytool` keychain profile)

## Reusing this for a future sibling project

Copy `Installer/` wholesale into the new project, then edit only:
1. `PRODUCT_NAME`/`COMPANY_NAME`/`BUNDLE_ID` and `project(... VERSION ...)` in the new project's root
   `CMakeLists.txt` (covers product name, version, publisher, bundle ID everywhere below).
2. `CrystalBowie.iss`'s `AppId` — generate a fresh GUID (`[guid]::NewGuid()` in PowerShell). Rename the
   file itself and the two `Windows`/`macOS` script filenames if desired; nothing else references them
   by name except each other.
3. `assets/icon-source.png` — replace with the new project's artwork, then re-run `generate_icons.py`.
4. If the plugin ships a different format set than CLAP/VST3/AU, adjust `CrystalBowie.iss`'s
   `[Components]`/`[Files]` sections and `build_installer.sh`'s `pkgbuild`/`distribution.xml` blocks
   accordingly — those are the only format-specific parts of either script. Also check whether the new
   project's VST3 build is a single file (clap-wrapper) or a folder bundle (JUCE) — that changes whether
   the `[Files]` entry needs a wildcard + `recursesubdirs`.

No shared config-file format/engine was introduced beyond the generated `ProductInfo.iss`/`.sh` pair,
following the same precedent set by `_IAFX-Collection/ceiling`'s installer.
